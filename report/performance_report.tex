\section{Goal}

The goal of profiling was to compare a simple baseline implementation with an
optimized implementation used in the project. The project converts RGB images to
black-and-white modes with several algorithms.

\section{Data}

The benchmark script generates deterministic RGB images with random pixel values.
The tested image sizes are 256x256, 512x512 and 1024x1024 pixels.

\section{Baseline}

The baseline implementation processes every pixel in nested Python loops and
calculates luminosity with the formula:

\[
gray = 0.299R + 0.587G + 0.114B
\]

\section{Bottleneck}

The main bottleneck is per-pixel Python iteration. Every pixel access goes
through Python objects, so the cost grows quickly with image size.

\section{Optimization}

The optimized implementation converts the image to a NumPy array and applies
vectorized operations to all pixels at once. This reduces Python-level loops and
moves most work to optimized native code.

\section{Conclusion}

The optimized NumPy implementation is the selected production approach because
it avoids slow Python pixel loops. This is a real performance improvement, not a
bug fix: the algorithmic result stays the same while the implementation changes
how pixels are processed.
